# 기존 PyTrading 코드 재사용 검토

이 검토는 실제 로컬 소스와 오프라인 테스트에 근거한다. 수익성·실제 체결 검증이 아니다.
새 실행 위치는 `C:\Projects\PyTrading\Code`이며 현재 `main.py`는 기존 rule-trader의 17종목 장중 모의 엔진이다.
기존 PyTrading 기능은 자동 연결하지 않았다. 매매 기준 변경과 기존 보유분 청산을 피하기 위해 검토와 통합을 구분한다.

## 그대로 가져오지 않을 부분

- 기존 메뉴형 `src/main.py`: 한 번 실행하고 종료한다. 새 프로그램의 인자 없는 지속 실행을 대체하지 않는다.
- 기존 종가 손절: 현재 유효한 호가를 검사하는 장중 가격 보호를 대체하지 않는다.
- KIS pickle 토큰: 백업에 보존한다. 기존 파일을 실행 중 불러오거나 새 모의 엔진에 연결하지 않는다. 향후 JSON·최소 비밀 저장으로 수정한다.
- 고정 투자 유형·목표 비중·손절 폭: 과거 프로그램의 가설이다. 테스트 통과가 투자 기준의 안전성·수익성을 입증하지 않는다.
- 실제 보유 CSV·추천 상태: 복사된 모의 계좌로 변환하지 않는다. 기존 보유분에 새 손절을 소급 적용하지 않는다.

## 확인한 주의점

- CORE 설명은 단계적 축소를 강조하지만 실제 조건에 따라 한 번에 50% 축소 의견도 나온다. 통합 시 화면·문서와 조건을 일치시켜야 한다.
- TACTICAL의 ATR 기반 신규분 손절은 10~15% 범위다. 현재 장중 3% 손절과 다른 규칙이며 직접 치환하면 위험 기준이 달라진다.
- 기존 추천 엔진은 과거 최초 수량을 레거시로 두고 이후 CSV 증가분만 추적한다. 실제 체결 내역이 없는 추정 상태이며 실계좌 동기화가 아니다.
- 시세·보유 모델과 통화 기준이 달라 파일만 복사해서 연결하면 안 된다.

## 검증과 다음 통합 순서

기존 전체 오프라인 테스트 52개 통과, 현재 장중 프로그램 전체 오프라인 테스트 169개 통과.
합성 입력·모의 API에 대한 기능 검사다. 실제 토스/KIS 연결, 이식 후 장중 운용, 수익성은 이번 이전에서 미검증이다.

1. 현재 엔진 성과 보고에 월별 손익·최악의 월·연속 손실·샤프 등을 추가한다.
2. 보유 관리 계층에 투자 유형·비중 한도·부분 매도를 별도로 설계한다.
3. 기존 단계적 청산을 독립 후보로 비교하고 원가·이익 보호와의 충돌을 검증한다.
4. 필요할 때 KIS 공급자를 데이터 변환 계층으로 연결한다.

이번 작업으로 매매 조건을 바꾸거나 수익률이 개선됐다고 주장하지 않는다.
원본 코드·테스트·보유 파일의 전체 백업 위치는 [이전 안내](MIGRATION.md)에 기록했다.

이 문서의 장비 이름, 사용자명 및 절대 경로는 공개용 예시다. 실제 환경에서는 로컬 값을 사용한다.
