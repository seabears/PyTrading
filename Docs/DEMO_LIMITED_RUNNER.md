# 한정 모의 주문 실행부와 계좌 관측 원장

## 판단 순서

1. 실제 정규장 복구 원본의 시각/종목 연속성을 확인한다.
2. vps 인증·계좌·원장 지문을 묶고 사용자 확인 초기 가상 현금100000 USD를 별도 기준으로 기록한다.
3. 전체 주문 이력을 양끝에서 읽고 NASD/NYSE/AMEX 잔고·예약·매수 여력을 대조한다.
4. 확인한 수량·주문·미확정 비용을 같은 SQLite의 risk_observations/demo_settlement에 보존한다. 현재 현금/NAV·순손익·비용을 임의값으로 만들지 않는다.
5. 완전한 실제 현금·비용·자금 사건 근거가 확보되면 기존 RiskLedger 검산과 주문 스냅샷 대조를 거친다. 현재 이 실제 공급기는 미구현이며 승인false다.
6. 승인된 경우에만 명시 시험 실행부가 취소 시험→매수→보유 확인→매도→최종 대조를 수행한다. 최초 시험 주문이 먼저 체결되면 추가 매수를 생략한다.
7. UNKNOWN/SENDING·응답 유실·페이지/계약 불일치에서는 재조회만 하고 자동 재전송하지 않는다. 종료 후 항상 주문 허가를 닫는다.

## 프로필과 단위

Config/kis-demo-session.json: symbol(주식1종목), quantity(1주), 최대 동시1주, maximum_gross_buy_commitments_usd(USD500), 매수전송2회·매도2회·취소2회·활성10분 상한을 유지한다. 기존 위험 한도가 더 엄격하면 그것을 적용한다. 취소된 의도도 누적 예산에 남으며 기존1.003 예약 완충을 포함한다. 이는 확정 수수료율이 아니다.

buying_power_service의 integrated는 프로필 검사부터 거절한다. unknown은 신규 매수를 차단한다. cash_only는 사용자 요청이며 계좌 확인 결과가 아니다. 등록된 공식 계좌 상태 파서의 동일 계좌·모드·확인 시점·원본 해시 근거에서 통합증거금과 사후 자동환전이 모두 꺼진 것으로 확인돼야 한다. 현재 공식 계좌 상태 응답 계약을 확보하지 못해 운영 파서 목록은 비어 있으며 실제 계좌 상태는 unknown이다. 가입·활성화·해지를 자동으로 수행하지 않는다.

확인 근거는 cash_service_evidence에 출처·계좌 지문·모드·confirmed_at·두 명시적 상태값으로 보존한다. 주문용으로는 동일 프로세스에서 받은 30초 이내 근거만 유효하며 재시작 후 다시 확인해야 한다. 30초는 기존 계좌 스냅샷 유효시간과 같다. 수동 verified 플래그나 저장 JSON 복사로 승인하지 않는다. 프로필→여력 선택→RiskLedger→OrderManager→KIS 관리 주문→실제 HTTP 직전(호출 간격 대기 후 포함)에서 재검사한다. 원주문이 확인된 안전한 보유 축소·취소의 별도 경로는 유지한다.

비통합 계좌 확인 뒤에만 ovrs_ord_psbl_amt를 주문 여력으로 선택한다. 이 값도 실제 USD 현금이나 NAV가 아니다. frcr_ord_psbl_amt1 등 통합 관련 필드는 읽기 전용 진단에만 남긴다. 과거 외화100000·통합 관련99000은 이전 관측값이며 현금·손익·대출·서비스 가입 상태로 추정하지 않는다. 현재 위험 승인과 실제 주문은 계속 차단된다.

poll_seconds(초)는2~30, maximum_poll_count는1~60이며 조합이 활성 시간 상한을 넘으면 거절한다. 기본5초/24회다. 전체 실행의 벽시계 상한과 API 페이지 전송 전 중단 검사를 적용한다. 정리 단계는 최대120초 별도 조회/취소를 허용하되 취소의 최초 활성 만료+2분과 원주문 증거 제한이 우선한다. 진행 중 HTTP는 기존15초 상한이 있다.

initial_reference는 사용자 확인 초기 가상 현금이다. 이를 실시간 현금·순자산·verified 플래그로 복사하지 않는다. 과거 이력을 검증했다는 뜻도 아니다. 현재 진짜 현금/정산 근거가 없으면 새 매수를 차단한다.

## 비용 대기와 보유 축소

누적 체결 수량·금액은 주문별로 대체 저장하여 중복 통보를 더하지 않는다. 개별 체결 ID/시각을 주문 접수시각에서 만들지 않는다. 확정 비용은None/PENDING_EVIDENCE, 순실현손익도None이다. 새 매수는 기존 RiskLedger를 계속 요구한다.

반면 동일 프로세스에서 전체 이력·보유·매도가능·예약과 원주문 계약을 새로 대조했다면 비용 미확정이어도 보유 축소 매도를 별도로 검사할 수 있다. 한정 시험은 자기 실제 체결량 이내만 매도한다. 다른 계좌·원주문 변경·수동 거래·수량 불일치·오래된 호가/관측·복구 중지·replay 원장·불명 주문은 거절한다. 축소용 활성화로 매수할 수 없다. 취소도 원주문 식별·잔여 수량과 유효 시각이 필요하다.

현재 합성 검사에서 이 경로를 검증했고 실제 vps 체결로 검증하지는 않았다. 체결을 만들기 위해 가격을 무제한 수정하지 않으며 제한 내에 정리하지 못하면 REVIEW로 잔여 수량·미체결을 보고한다.

## 이어받기와 종료

resume_store=null이면 새 시험 원장을 만든다. 기존 시험을 이어받으려면 이전 결과의 store 경로를 Config.resume_store에 명시한다. Data/execution/kis-demo-session 밖, 다른 모드·별칭·계좌·프로필 한도 변경은 거절한다. 원장 파일을 새 계좌로 복사해 승인하지 않는다. 원격 전체 대조 전에는 매수가 열리지 않으며 SENDING/UNKNOWN은 재전송하지 않는다. 이전 활성 만료 시각도 늘리지 않는다. 만료된 시험은 정리 필요 상태로 남을 수 있다.

Ctrl+C/종료 요청 시 추가 주문을 멈추고 확인된 자기 주문의 제한적 정리·최종 조회를 수행한다. 조회 실패 시 잔여를0으로 추정하거나 완료로 쓰지 않는다. Config.enabled를 켜는 것으로 주문이 시작되지 않는다. 기본 진입점은 조회 전용이고, 별도 명시 진입점과 위험 승인·자동 승인 검토가 모두 필요하다.

## 실행

Windows CMD:

    cd /d C:\Projects\PyTrading
    %USERPROFILE%\AppData\Local\Programs\Python\Python312\python.exe Code/main.py --test all

실제 조회는 Code/kis_demo_session.py --recovery-file <최신Pi검증JSON> --env-file Credentials/kis_demo.env --output <Data하위새폴더> --contracts-folder <공식계약폴더> 로 수행한다. 원본 checked_at은30초 이내여야 하며 읽은 시각으로 바꾸지 않는다.

Code/kis_demo_execute.py --execute-limited-demo는 한정 주문 진입점이다. 이번 작업에서는 자동 승인 검토가 해당 실행을 거부했으므로 실행하지 않았다. 현재 필요한 실제 위험 근거가 부족하며 명령을 바꿔 우회하면 안 된다. 조회 전용 Code/kis_demo_session.py로만 실제 검증했다.

라즈베리파이: 운영 서비스는 유지하고 부팅 자동 시작disabled다. 새 실행부는 운영 경로에 배포하지 않았으며 격리 ARM 경로에서만 검사했다. 신규 서비스를 등록하지 않았다. Linux 핵심 검사는 해당 격리 폴더에서 .venv/bin/python Code/main.py --test all 이다.

이 문서의 장비 이름, 사용자명 및 절대 경로는 공개용 예시다. 실제 환경에서는 로컬 값을 사용한다.
