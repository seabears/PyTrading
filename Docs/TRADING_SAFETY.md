# 매수·매도 판단 안전장치

현재 모의 계좌 경로에 적용한다. 실제 증권사 주문 전송의 위험 통제·주문 취소·체결 대사 검증을 끝냈다는 뜻이 아니다. 실주문 경로는 연결하지 않았다.

## 공식 공시 참고 사이트

뉴스 RSS는 발견 경로이며 공시 원문으로 간주하지 않는다. 원문·분기·회계 기준·발표 전 예상치 증거가 없는 실적은 매매 근거로 올리지 않는다. 현재 [실적 원문 감사](../Data/reports/earnings-audit/report.md)와 [추가 수집 계획](EARNINGS_DATA_PLAN.md)을 함께 확인한다.

## 적용한 제한

설정은 `Config/safety.json`, 계산은 `Code/trading/safety.py`, 적용 지점은 `Code/trading/paper.py`다. 금액은 KRW·USD를 합치지 않고 시장별로 계산한다.

|제한|기본값·의미|
|---|---|
|일일 손실 중단|당일 첫 유효 관측 직전 저장된 순청산 평가액 대비 손실 2% 이상이면 그날 신규 매수 중단. 현금·미청산 평가·가정 매도 비용 포함|
|거래별 예상 위험|초기 시장 자금의 0.5% 이내. 평균 원가 기준 초기 손절선까지의 손실과 매도 비용으로 수량을 줄임|
|한 번의 매수|초기 시장 자금 10% 이내|
|전체 보유|최대 5종목, 총매입 원가 초기 시장 자금 50% 이내. 시가 평가가 오른 것을 매입 원가 한도와 혼동하지 않음|
|일일 매수 횟수|시장별 거래일 최대 10회|
|연속 손실|당일 최근 매도 3건 연속 순손실이면 마지막 손실 매도 후 60분 신규 매수 대기|
|보유 시세 누락|다른 보유 종목의 호가 관측 시각이 없거나 180초 초과면 신규 매수 보류|
|갑작스러운 시세 변화|같은 날 5분 이내 직전 관측 대비 중간 호가가 10% 초과 변하면 해당 매수 보류|
|수동 중지|출력 계좌 폴더에 `PAUSE_BUYS`라는 빈 파일이 있으면 신규 매수 중단|
|기존 시세 안전 검사|현재 호가 30초 이내·미래/역전/비정상 가격 차단, 완성·연속 봉·거래량·스프레드·추격 제한|
|기존 중복 방지|같은 종목·시각 재처리 금지, 같은 봉 재매수 금지, 매도 후 재진입 대기, 계좌 단일 프로세스 잠금|

일일 거래일은 미국 America/New_York, 한국 Asia/Seoul 기준이다. 한국 자정에 미국 장의 매수 제한을 초기화하지 않는다. 일일 기준과 손실 중단 상태는 account.json에 보존해 재시작으로 해제되지 않는다. 다음 현지 거래일의 유효 관측에서 새 기준을 만든다.

일일 기준은 마지막으로 저장된 관측 평가액이며 거래소의 공식 시가 평가나 증권사의 공식 일일 손익은 아니다. 보유 호가가 오래되면 평가는 이전 관측값을 포함할 수 있어 신규 매수를 보류한다. 손절선의 0.5% 예상 위험은 갭·거래 정지·체결 지연 시 실제 손실 상한을 보장하지 않는다.

매수 제한은 가격 손절·추적 보호·정상적인 보유 매도를 차단하지 않는다. 매도에는 유효한 정규장 호가가 필요하며, 보유한 모의 수량만 청산한다. 수동 중지가 모든 매도를 막는 기능은 아니다.

## 긴급 신규 매수 중지

기본 출력 위치 `Data/paper-kis/` 안에 확장자 없는 `PAUSE_BUYS` 빈 파일을 만든다. 실행 중에도 다음 판단부터 읽는다. 파일을 없애면 다른 제한이 없는 경우 신규 매수를 다시 허용한다. 가격 손절은 계속한다.

그 외 Config/safety.json 수정은 프로그램 재시작 후 적용된다. 기존 계좌의 현금·거래 기록을 초기화하지 않는다. 기존 계좌에 보유 호가 시각이 없으면 실제 시세가 다시 수집될 때까지 신규 매수를 대기한다.

관찰 종목 목록에서 빠져도 기존 보유 종목은 시세 검사 대상에 자동 추가한다. 한 종목의 시세 수집 오류가 나도 다른 보유 종목 검사를 계속한다.

## 계좌·저장 안전

기존 저장 상태의 현금과 거래 현금 흐름, 수량과 원가를 대조한다. 손상되면 새 계좌로 조용히 초기화하지 않고 오류로 중단한다. 매수·매도 저장 실패 시 메모리 상태도 이전 값으로 되돌리며 원자적 임시 파일 교체 방식을 유지한다. 설정 변경이나 실패 복구를 위해 기존 account.json을 삭제하지 않는다.

## 실행과 검증

```cmd
python Code/main.py
python Code/main.py --test safety
python Code/main.py --test unit-safety
```

평소 실행 인자는 추가하지 않았다. safety는 별도 임시 계좌·합성 시세로 정상 매수→매수 중지→손절 매도 흐름을 보인다. 실제 공시·시세·증권사 인증·주문을 호출하지 않는다. 최신 결과는 [검증 보고서](../Data/reports/safety/report.md).

이전 저장 평가 가격 자체가 없어 당일 기준을 정할 수 없는 구형 계좌는 `safety_valuation_unavailable`로 당일 신규 매수를 보류한다. 현재 유효 호가에 따른 보유 손절은 계속하며, 임의의 평가 가격이나 일일 기준을 만들지 않는다.
