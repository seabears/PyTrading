# 주문 대조·취소 재검토 수정 — 2026-10-27

기존 514개 자동 검사가 통과해도 두 추가 경계 사례는 실패했다. 두 사례를 Test/trading/test_review_regressions.py에 먼저 편입해 실패를 보존한 뒤 수정했다. 입력은 임시 SQLite와 합성 KIS 응답이며 실제 증권사 체결 검증이 아니다.

## 주문 대조

주문번호만으로 대조하지 않는다. 모드·계좌 지문·주문일·주문번호·종목·방향·원수량·지정가 유형·가격·원주문 연결을 확인한다. 숫자 문자열의 선행 0과 소수 표현 차이만 정상화한다. 중복 ID·필드 누락·다른 계좌/주문·누락 페이지·수동 주문은 신규 주문을 중지한다. 실패 원인은 last_reconcile_error의 기계 코드에 남기며 응답 원문·계좌번호는 저장하지 않는다.

대조는 복사본에 전체 적용한 뒤 한 번 저장한다. 뒤쪽 주문 검사가 실패해도 앞쪽 체결이나 계좌 변경을 일부 저장하지 않는다. 오래된 누적 조회는 새 주문 허가 근거가 되지 않는다. 직접 체결 통보의 중복·역순 억제와 재시작 잠금은 유지한다.

## 예약 수량과 취소

전체 보유 positions, 원격 매도가능 sellable, 원격 미체결 예약 remote_reserved_sell, 로컬 미전송 예약을 나눈다. 보유 5·원격 매도 2·가능 3은 설명되는 상태다. 새 매도는 순가능 3에서 로컬 미전송 예약만 차감한다. 이미 서버에서 차감한 매수가능 외화와 원격 예약을 다시 차감하지 않는다. 전체 투자 노출 한도에는 아직 체결되지 않은 매수 위험도 포함한다. 설명되지 않는 차이는 중지한다.

ready는 신규 주문 자격이다. 취소는 별도의 주문별 검산 증거를 요구한다. 완전한 최신 조회에서 계좌·원주문 불변 필드와 잔여 수량을 확인한 주문만 취소할 수 있다. 계좌 자금 대조나 수동 주문 때문에 신규 주문이 중지돼도 확인된 원주문 취소는 가능하다. 다른 계좌·원주문 미확인·중복 ID·불완전 조회에서는 취소도 허용하지 않는다. 증거는 재시작 시 재사용하지 않고 다시 조회한다.

취소 상태는 NOT_SENT(전송 전 실패), SENDING, ACCEPTED(접수, 최종 취소 아님), REJECTED(명시 거절), UNKNOWN(전송 뒤 응답 유실), CONFIRMED 또는 FILLED_DURING_CANCEL로 구분한다. 전송 전 실패를 CANCEL_PENDING으로 남기지 않는다. UNKNOWN은 일반 미체결 조회만으로 해제하거나 재전송하지 않는다. 이미 확인된 취소 접수 번호의 명시 거절은 원주문 상태로 대조할 수 있다. 접수 번호가 유실된 불명 취소는 수동 연결 근거가 필요하다.

취소 자식 행의 0 가격과 취소 요청 수량을 원주문의 주문 가격/원수량으로 덮어쓰지 않는다. 원주문 번호·날짜·종목·방향이 유일하게 연결돼야 한다. 원주문 누락·동일 번호의 날짜 간 모호성은 중지한다. 관리되지 않은 정정(01)은 지원 성공으로 꾸미지 않고 수동 대조 대상으로 차단한다. 자동 실행 경로는 현재 미국 모의 지정가 원주문과 취소(02)만 지원한다.

공개 예제의 필드 의미를 확인한 것이며 실제 계정에서 예약 시점·재사용 금액·처리상태 문자열·자식 행의 반환 방식까지 검증한 것은 아니다. 실제 모의투자 계약 검증 전 자동 연결하지 않는다. 유형 필드가 없는 미국 모의 조회는 이미 확인된 지정가 전용 요청 범위에서만 LIMIT로 처리하며 일반 주문 유형을 추측하지 않는다.

## 남은 외부 연결 조건

검증된 위험 원장(초기 자금·일별 기준·연속 손실), 수동 거래와 타 프로그램 주문 대조, SQLite backup API를 사용하는 주문 원장 백업/복구와 미완료 상태 재대조, 실제 KIS 모의 응답·페이지·취소 경합·부분 체결 검증이 필요하다. 내부 PaperAccount 복구를 증권사 주문 원장 복구로 대신하지 않는다. 실계좌 송신 차단·상품 제한·신용 금지·FMP 제외 정책은 그대로다.
