## 연결한 기능

Code/trading/demo_cash_review.py는 기존 사용자 현금 모델·잔고 캡처·정규화된 전체 주문 이력·최신 API 여력을 검산한다. 계좌 지문/모드/원본 해시/30초 유효시간, 초기 기준부터 현재 현지 날짜까지 조회 범위, 모델과 주문 누적치 일치, 보유/원장 연결을 요구한다. 결과를 기존 RiskLedger.record_unsettled_observation으로 주문과 같은 SQLite에 보존했다. 승인된 RiskProof와 혼동하지 않는다.

Code/kis_demo_balance.py와 DemoExecutionPort.refresh 양쪽에 cash_risk_review 출력을 연결했다. 기본 조회 도구에서 주문 허가를 켜지 않고 실행 가능하다. 이전 pending 관측에 남던 non_integrated_account_status_unproven 차단 문구도 제거했다. 기존 이력을 삭제하지 않으며 가입 상태 자료를 다시 요구하지 않는다.

현금 계산은 사용자 지정 초기100000 USD + 누적 매도대금 - 누적 매수대금 - 확인된 비용이다. 사용자 기준의 출처와 최초 등록시각은 그대로 보존한다. API 주문가능액을 초기금이나 현금으로 복사하지 않았다. 같은 체결의 누적값 재조회가 중복 지출을 만들지 않는다.

API 한도에서는 이미 대조된 원격 예약을 재차 차감하지 않고 로컬 미반영 예약만 차감한다. 현금 상한에서는 원격·로컬 잔량 예약을 각각 한 번 확보한다. 두 한도 중 작은 값을 잠정 추가 예산으로 표시한다. 비용 예약 완충1.003(0.3%)은 실제 수수료율이나 확정 비용이 아니다. 미확정 체결 비용은 별도로 추정 표시하고 확정 비용은 None으로 유지하며 신규 매수는 차단한다. 미체결 예약은 손익으로 잡지 않는다.

계좌에 로컬 원장과 매칭되지 않는 수동 주문이 있거나 SENDING/UNKNOWN 상태가 있으면 별도 사유를 표시한다. 보유를 임의 정리하거나 계좌 상태를 바꾸지 않는다. 취소/추가 체결의 기본 상태 처리는 기존 구현과 회귀 검사를 유지했다.

## 남은 차단 사유를 구체적으로 구분

1. cash_movement_coverage_not_established: 주문/체결 조회만으로 입출금·환전·배당 등 모든 사건이 없었다고 증명할 수 없다. 이번 조회 범위 2026-11-01~2026-11-01, 모델 최초 등록 2026-11-01T10:40:15.941818+00:00. 이 이전 기간을 검증하지 않았다. 모의 지원 원본 또는 공식 화면·명세 등 자금 사건 확인 경로가 필요하다.
2. current_approved_risk_checkpoint_missing: 계산 결과는 같은 RiskLedger의 미확정 관측에 저장됐으나 주문용 승인 평가가 아니다. 기존 resolve_available_sources는 공식 현금/자금 사건 공급기 미연결로 sources=None을 반환한다. 사용자 지정 현금 모델을 공식 kis_vps 현금 자료로 위장하거나 verified=True로 승인하지 않았다. 공급 자료의 범위와 출처에 맞는 위험 평가 연결이 다음 구현 조건이다.

현재 체결0이므로 '기존 체결 비용 미확인'을 차단 사유로 만들지 않았다. 향후 비용 경로가 미확정이라는 별도 제약은 남는다. 첨부 문서에 일반 정산 시점은 있으나 모의 최종 수수료를 제공한다고 확인한 것은 아니다. 자동 주문을 시도할 경우 이 부분을 해결하고 최신 정규장 시세·계좌·기존 한정 시험500 USD/1주 등 기존 조건을 재검사해야 한다.

사용자에게 초기금이나 통합증거금 가입 상태를 다시 요청하지 않는다. 필요한 외부 자료가 있다면 '같은 모의계좌의 등록 이후 자금 사건 명세'와 '모의 체결 최종 비용을 확인할 지원 화면/명세 또는 API 계약' 두 범위다. 현재 잔액 숫자가 맞다는 사실만으로 모든 이력을 검증했다고 처리하지 않는다. 이번에는 주문 실행이 요청 범위가 아니며 실제 주문0이다.
