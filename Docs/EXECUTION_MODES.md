# 체결 방식 선택과 기존 전략 실행

## 설정 한 곳

`Config/execution.json`의 internal_paper/kis_demo/live 각각 enabled를 true/false로 고른다. 한번에 하나만 true. 전부 false면 관측 전용이며 가상 체결도 저장하지 않는다. 둘 이상 true이거나 boolean이 아닌 값은 시작 전에 거절한다.

Windows CMD에서 메뉴로 변경할 수도 있다.

```cmd
cd /d C:\Projects\PyTrading
%USERPROFILE%\AppData\Local\Programs\Python\Python312\python.exe Code\execution_mode.py
```

모드 변경은 실행 중인 전략을 정상 종료한 뒤 하고 다시 시작한다. 실행 중 파일이 바뀌면 다음 판단에서 중단하여 기존 포지션을 다른 모드 계좌로 보내지 않는다. 내부/모의/실계좌의 데이터는 서로 합치거나 초기화하지 않는다. 모드 전환으로 다른 계좌의 보유 관리가 이어지는 것은 아니다.

## 적용 실행 파일

- Code/main.py: 기존 기본 전략.
- Code/price_paper.py: 기존 가격 연구 전략.
- Code/daily_paper.py: 고정 일봉 후보. 규칙·매수창·손절·수량 계산을 재최적화하지 않는다.

세 실행 파일 모두 같은 체결 설정을 사용한다. main.py의 오프라인 replay는 설정과 관계없이 내부 가상체결로만 재생한다. KIS 모의계좌 하나의 원장은 전략들이 공유하므로 여러 프로세스에서 동시에 열면 잠금으로 거절한다. 내부 전략별 비교 계좌와 증권사 주문 원장은 별개다.

## 모드별 실제 동작

|모드|동작|이번 검증 범위|
|---|---|---|
|internal_paper|기존 내부 가상체결과 비용 가정 그대로|전체 회귀 검사|
|kis_demo|실제 KIS 시세의 전략 판단·원본 수량을 기존 모의 주문 관리자에 전달|합성 접수/중복/응답유실/수량 보존 검사. 실제 전략 주문 체결은 미실행|
|live|설정 선택 가능, 전송 잠금 유지. 선택 시 인증/주문 전에 명확히 중단|실계좌 요청0 검사. 실계좌 실행 가능 상태 아님|

내부 계좌는 기존 경로를 보존한다. 증권사 모드 전략 투영은 Data/execution-accounts/<mode> 아래, 모의 주문 원장은 Data/execution/kis_demo/strategy-orders.sqlite다. 기존 내부 가상 체결을 실제 보유로 복사하지 않는다. API 접수만으로 수량·현금·거래를 바꾸지 않고 전체 원격 누적체결 대조로만 보유를 갱신한다. 중복 신호·재시작·응답 유실은 자동 재주문하지 않는다. 원문 예외/인증/계좌번호를 상태 기록에 넣지 않는다.

한정 주문 시험의 강제 종목·1주·500USD·체결 직후 매도는 이 경로에 적용하지 않는다. 기존 전략의 수량과 매도 신호를 전달하되 기존 상품·USD 현금·위험·계좌 대조 검사는 계속 적용한다. 거절/미체결도 체결 성공으로 기록하지 않는다. 증권사 모드는 추정 비용을 실제 확정 수수료·손익으로 보고하지 않는다.

## 사용자 지정 모의 초기금과 실제 계좌 대조

사용자가 이미 지정한 초기100000 USD와 최신 빈 모의계좌/전체 주문 이력/순수USD여력/대출0/매도대금재사용0을 검산해 일반 전략의 최초 진입 근거를 생성한다. 금액을 현재 공식 현금/NAV로 복사하지 않으며 broker_cash_verified=false/past_cash_movements_verified=false를 보존한다. 사용자 지정 자금 모델에 의한 모의 실행이며 실계좌 근거로 사용할 수 없다.

공식 전체 과거 자금 이력이 확인됐다고 기록하지 않는다. 빈 계좌와 예약0에서 모델 금액과 USD여력이 다르면 입출금이 없다고 가정하지 않고 차단한다. 원본 해시/계좌/환경/기간/30초 신선도/양끝 전체이력 대조·OS잠금·중지/복원 상태를 검사한다. 저장된 eligible값만으로 재시작 후 승인하지 않는다. 원본 캡처와 런타임 모드 연결을 다시 확보한다.

수량·매수/매도 시점은 기존 전략을 따른다. 한정 시험의1주/500USD/2회/즉시 매도 규칙을 일반 전략 경로에 넣지 않았다. 기존 전략의 투자 비중과 공통 주문 위험·손실 한도는 유지한다. 최초 실제 체결 후 비용이 미확정이면 신규 매수를 차단하고 확인된 보유의 기존 손절/매도 신호는 별도 감소 전용 검사로 관리한다. 이 단계의 사용자 모델 근거는 아직 정산되지 않은 체결이 없는 최초 진입 구간을 대상으로 하므로, 무제한 반복 매매/지속 수익성이 검증됐다는 뜻이 아니다. 비용 원본과 실제 현금 변동 정산이 완료돼야 다음 신규 진입 기준을 확대할 수 있다.

실제 검증은 최신 보고서를 따른다. 최초 진입 근거 통과와 실제 주문 접수/체결·수익성 확인은 구분한다. 체결이 없는 현재 비용의 해당 없음과 향후 비용 경로 미확인은 별개다. 증권사 모드는 추정 현금/원가를 전략 계산 투영으로만 쓰고 실제 손익 보고를 만들지 않는다. 같은 계좌 원장을 여러 프로세스가 동시에 열 수 없다. 실계좌는 여전히 전송 잠금이며 enabled=true도 잠금을 해제하지 않는다.


## 체결 후 정산 연결 개발 (2026-11-03)

정산 원본 소비·비용/자금 사건 대조·후속 위험 재평가와 읽기 전용 상태 명령을 추가했다. 실제 KIS 정산 자료 공급기는 기본 미연결이며 운영 반복 체결 완료로 표시하지 않는다. 최신 범위와 사용법은 [STRATEGY_POSTTRADE.md](STRATEGY_POSTTRADE.md)를 따른다.


## 진단·취소·계획 식별 수정 (2026-11-03)

--test 진단은 증권사 모의/실계좌 주문을 금지하며 전역 모드와 무관하게 내부 가상체결만 사용한다. NOT_SENT 취소는 최신 잔량 대조 뒤 재시도할 수 있고 UNKNOWN/접수/거절은 자동 반복하지 않는다. 일봉 계획은 같은 계획 ID와 주문 해시의 실제 체결로만 집행 처리한다. 상세 및 검증 근거는 [EXECUTION_REVIEW_FIXES.md](EXECUTION_REVIEW_FIXES.md)를 따른다.

이 문서의 장비 이름, 사용자명 및 절대 경로는 공개용 예시다. 실제 환경에서는 로컬 값을 사용한다.
