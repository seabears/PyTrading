# 실적 예상치 제공원 점검과 모의매매

> 현재 방침: FMP는 사용하지 않는다. API 키 발급·연결·수집 대상에서 제외한다. 다른 유료 제공원도 자동으로 도입하지 않는다.

2026-10-25 실제 공개 응답 점검. 자세한 원본·수치·그래프는 `Data/reports/consensus-sources/report.md`에 보존한다.

## 제공원 결과

- Alpha Vantage 공개 IBM 데모: EPS·매출 예상치 80개 지표 관측을 저장했다. 이 중 미래 회계기간 후보는 4개이며 매매 승인 자료는 0개다. 80개 기업이나 80개 거래라는 의미가 아니다.
- 개인 API 키를 사용한 전체 종목 권한·최신성·실적 발표 전 수집 가능성은 아직 검증하지 않았다.
- GAAP/조정 EPS 기준, 통화·단위, 기간 시작, 발표 시각이 불명확해 추측하지 않았다. IBM 보고 EPS를 SEC GAAP EPS와 그대로 섞어 surprise를 계산하지 않는다.
- 달력은 HTTP 200이지만 헤더만 받았다. 예정 실적 발표가 없다는 의미로 해석하지 않는다.
- 과거 FMP 무인증 요청은 HTTP 401이었다. 이후 사용자 요청으로 FMP 사용을 중단했으며 후속 인증·데이터 비교는 진행하지 않는다.
- Alpha Vantage는 개인 키 연결 시험 후보일 뿐 운영 제공원 확정이 아니다. 일반 무료 한도 하루 25회로 30종목 매일 조회도 초과한다. 개인 키의 해당 기능 접근 권한은 별도 확인해야 한다.

## 모의매매는 어떻게 동작하는가

현재 프로그램은 KIS 실제 시세를 조회하고 로컬 가상 계좌의 현금·보유 수량·거래 내역을 갱신한다. 증권사에 실제 주문이나 모의 서버 주문을 보내지 않는다.

체결은 매수 호가가 아니라 매도 호가(ask)에 불리한 슬리피지를 더해 매수하고, 매수 호가(bid)에서 슬리피지를 빼 매도하는 가정이다. 기본 슬리피지는 0.1%, 매수 비용 0.1%, 매도 비용 0.2%다. 실제 부분 체결·대기열·시장 충격을 완전히 재현하지 않는다.

`Code/main.py`를 실행하고 있어야 시세 관찰과 판단이 계속된다. 현재 검증된 실적 사건이 없어 실적 기반 신규 매수는 대기하며, 유효한 시세의 기존 보유 보호 매도는 계속 판단한다.

과거 보고한 수익률은 과거 시세 백테스트 결과다. 최근 BUY/SELL 기능 검증에는 합성 입력도 사용했다. 상시 실시간 모의 운용 수익을 달성했다는 의미가 아니다.

## 다음 단계

1. 개인 데이터 키를 별도 인증 파일에 저장하고 소수 종목의 예상치·달력 접근 권한을 확인한다. 키를 채팅이나 코드에 적지 않는다.
2. 발표 전 실제 수신 시각과 원본·해시를 누적한다. 응답의 과거 수정 이력을 과거 수집 기록으로 바꾸지 않는다.
3. 발표 후 IR·SEC의 동일 기간·기준·단위 실적과 대조한다.
4. 검증 통과 자료로 비용 반영 모의매매를 관찰하고 거래 수·손익·낙폭을 평가한다. 현재 수익성은 미검증이다.

## 기능별 실행

CMD에서 프로젝트 루트로 이동한 다음 실행한다.

```cmd
python Code/main.py --test consensus
python Code/main.py --test unit-consensus
```

첫 명령은 이미 저장한 실제 응답의 해시·기간·불명 기준을 점검하고 보고서를 만든다. 새 API 데이터를 받거나 모의매매를 시작하는 명령이 아니다. 두 번째는 결측값·중복 기간·시간대·데모 매매 차단 등 14개 자동 테스트다.
