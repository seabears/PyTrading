# 진단·취소·일봉 계획 검토 오류 수정

2026-11-03. 실제 KIS API·증권사 모의 주문·실주문 없이 임시 계좌와 합성 응답으로 검사한다. 이번 변경은 실제 정산 공급기 미연결 문제의 해결이나 실거래 허가를 뜻하지 않는다.

## 1. 진단은 증권사 주문 경로를 사용하지 않는다

`python Code/main.py --test runner`는 현재 Config/execution.json이 kis_demo/live여도 별도 내부 가상계좌로 실행한다. `Code/tools/run_once.py`를 직접 호출해도 같은 제한을 적용한다. 운영 설정 파일은 바꾸지 않는다. `operations-live` 및 다른 `--test` 기능 실행도 진단 범위에 포함한다. `all`/`unit-*`는 합성 전송 계약을 검사하므로 별도 자동 검사 경로와 기존 실제 네트워크 차단을 유지한다.

- `broker/diagnostic.py`의 호출 범위에서 `load_execution`이 내부 모의를 선택한다.
- `configure_account`는 진단 중 명시적인 증권사 계좌 구성을 거절한다. runner에서도 진단/재생은 내부 모의로 고정한다.
- KIS 공통 실행·managed 사전 검사·낮은 HTTP 전송 경계에서 금융 변경을 전송 전에 차단한다. 인증·시세/계좌 GET과 실시간 접속키 발급은 금융 주문으로 취급하지 않는다.
- 중첩 진단·예외 종료 후에는 원래 호출 범위로 돌아간다. 설정의 enabled를 변경하거나 운영 계좌를 진단 계좌로 재분류하지 않는다.

진단에도 인증·실제 시세/뉴스 수집은 있을 수 있다. “주문 없음”은 모의 서버의 증권사 주문/정정/취소도 없다는 뜻이다. 내부 가상체결은 별도 결과 폴더에 남을 수 있다.

## 2. 취소의 전송 여부는 원장 상태로 판단한다

과거 `strategy_cancel_requested` 불리언만으로 다음 취소를 막던 조건을 제거했다. `OrderManager.cancel`이 이미 전송 직전 의도를 영속 저장하므로 전략 계층의 중복 플래그를 전송 잠금으로 사용하지 않는다.

|취소 상태|자동 처리|
|---|---|
|미시도 / NOT_SENT|최신 전체 대조에서 원주문·계좌·잔량이 확인됐을 때만 재시도 가능|
|SENDING / UNKNOWN|응답이 불명확하므로 자동 재전송 금지|
|ACCEPTED / 최종 완료|접수·최종 상태를 조회하고 중복 취소 금지|
|REJECTED|명시 거절을 자동으로 반복하지 않음|

재시작·부분 체결 이후도 최신 `can_cancel` 근거와 `cancellation_quantity`를 사용한다. 오래된 근거나 식별 불명 상태는 전송하지 않는다. 접수를 최종 취소로 표시하지 않는다. 새 매수 위험 승인과 검증된 기존 주문의 취소 권한은 여전히 별개다.

## 3. 실제 집행한 일봉 계획만 완료 처리한다

과거 체결의 종목·방향만 보고 새로운 pending_daily 항목을 삭제하지 않는다. 동일 전략 소유자, 계획 ID, 종목·방향, 그 계획으로 생성한 불변 신호/주문 해시, 누적 체결 수량>0이 모두 맞아야 집행된 계획으로 본다.

일봉 전략이 판단에 실제 사용한 `daily_plan_id`를 반환하며, 주문 의도와 원장에 `strategy_daily_plan_id`로 보존한다. 보호 매도로 계획이 없는 경우는 None이며, 같은 종목의 미래 매도 계획으로 추정하지 않는다. 계획이 없는 일반 전략의 기존 신호 ID 계산은 바꾸지 않았다.

이전 버전에서 `strategy_signal_at=계획ID`로 저장한 주문은 기존 해시가 정확히 맞을 때만 호환한다. 식별자가 없는 과거 주문은 추정해서 새 계획에 연결하지 않는다. 새 주문 체결 0이면 계획을 보존한다. 정확히 연결된 부분 체결이 있으면 계획 집행으로 표시하고 남은 주문 수량은 주문 원장에서 계속 관리한다. 다른 날짜·다른 전략의 계획은 유지한다.

## 검사와 적용

Windows CMD에서 `python Code/main.py --test unit-readiness` 또는 전체 `python Code/main.py --test all`을 사용한다. Python 3.12 실행 환경을 사용한다. 최신 실행 수치·원본 실패 재현·ARM 경로·파일 해시는 Data/reports/execution-review/latest.json이 가리키는 보고서를 따른다. 기존 통과 수를 이번 결과로 재사용하지 않는다.

이번에는 운영 Pi 설치·서비스·부팅 설정을 변경하거나 실제 계좌에 주문을 보내지 않는다. ARM 검사는 인증/운영 원장이 없는 별도 경로에서 수행한다. 운영 반영은 별도 정상 종료·원장 백업·코드 백업·롤백 준비 후 수행해야 한다.
