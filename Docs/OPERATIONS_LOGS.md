# 토큰 갱신과 종목별 일일 판단 로그

운영에서 실제 토큰 발급을 요청해 성공·실패한 때만 기록한다. 메모리/파일 캐시 재사용과 단순 캐시 형식 이관은 갱신이 아니므로 기록을 늘리지 않는다.

## 인증 이력

프로젝트 Data 하위 토큰 캐시를 쓰는 실제 운영 클라이언트는 Data/logs/token-refresh.json을 공유한다. prod 시세·vps 계좌 환경을 각 행에 구분하며 성공·실패 합계 최근100건만 보관한다. 101번째 이벤트부터 오래된 한 건씩 제거한다. 키·토큰·계좌·헤더·서버 자유문은 받거나 저장하지 않는다. 발급/기록/만료 시각, 환경, 안전한 HTTP·오류 코드만 저장한다.

프로세스 간 잠금과 원자 교체를 사용한다. 같은 저장 보류 이벤트의 재시도는 중복되지 않는다. 저장 실패 시 이전 정상 이력을 보존하며 다음 인증 호출에서 같은 이벤트를 다시 저장한다. 이 때문에 실제 토큰을 재발급하지 않는다. 인증 실패 중 이력 저장도 실패하면 원래 인증 오류를 보존한다. 인증을 강제로 갱신하거나 기존 토큰 발급 시각을 실제 관측처럼 소급 입력하지 않는다.

프로젝트 외부 캐시(격리 검사 등)는 해당 캐시 폴더의 token-refresh.json으로 분리한다. 영속 캐시를 지정하지 않은 메모리 전용 시험 클라이언트에는 기록 파일이 없다. 모든 운영 시세·계좌 클라이언트는 기존 영속 캐시를 사용한다. 캐시 자체는 비밀 파일이며 이 로그와 다르다.

## 종목별 판단

실행 계좌 폴더/logs/decisions/US-YYYY-MM-DD/SYMBOL.jsonl에 한 판단을 한 줄로 기록한다. 날짜는 미국 뉴욕 현지 거래일이다. 한국 자정을 지나도 같은 미국 거래일 파일을 사용한다. 예: US-2026-11-04/T.jsonl.

각 행: 관측/KST 시각, 실행 모드, 매수·매도·보유·대기, 사유 코드, 호가와 호가 시각, 정규장 여부, 전략 소유 수량, 운영 중지, 계좌 대조 시각, 신규 매수 자격, 비용 대기, 신호 진단을 기록한다. 조회 실패도 안전한 단계·오류 분류로 남긴다. 임의 예외 문자열·응답 본문은 저장하지 않는다.

고정 일봉의 신호 진단은 해당 실행이 저장한 확정 일봉을 같은 함수로 읽기 전용 재계산한다. 전일 종가·이전55거래일 고가·봉 수·SPY200일 평균·조건 충족 여부·원본 해시를 포함한다. diagnostic_calculated_at은 현재 진단 시각, original_plan_calculated_at은 실제 원본 계획 계산 시각이다. 과거 자료 재생을 새로운 실시간 신호로 표현하거나 계획·체결·계좌를 변경하지 않는다. 원본 누락은 unavailable로 표시한다.

종목별 일일 로그에는100건 제한을 적용하지 않는다. 기존 decisions.jsonl 회전과 SQLite 원장도 보존한다. 매일 파일이 누적되므로 기존 저장 공간 감시를 유지한다. 불완전한 마지막 줄이나 저장 실패는 감추지 않고 운영 중지·안전한 오류 기록으로 처리한다.

Windows CMD에서 `python Code/main.py --test all`로 검사한다. Pi 적용은 기존 원장·계좌·설정을 보존한 코드 백업 후 해당 전략 프로세스만 정상 종료·재시작한다. 부팅 자동 시작·실계좌 허가·기존 위험 중지는 바꾸지 않는다.
